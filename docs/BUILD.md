# Build

## Requirements

| Tool | Version used | Notes |
|---|---|---|
| Visual Studio | 2026 (18.x) with .NET desktop development | Or the .NET SDK alone |
| .NET SDK | 10 or later (11.0.100 used) | Builds the .NET Framework projects and the HTREASURE standards CLI (`net10.0`) |
| .NET Framework targeting packs | not required | `Microsoft.NETFramework.ReferenceAssemblies` provides them |
| Inno Setup | 6.3 or later (6.7 used) | Release packaging only |
| Windows SDK `signtool` | optional | Only for verifying signatures; signing uses PowerShell |
| Git | any recent | Submodules |

## Get the source

```bash
git clone -c core.longpaths=true --recurse-submodules https://github.com/HTREASURE-LTD/HTREASURE-FileHashChecker.git
```

In an existing clone:

```bash
git submodule update --init
```

The two submodules are **private** HTREASURE LTD repositories, so the clone needs an account with access to the
HTREASURE-LTD organisation.

## Build and test

```bash
dotnet build HTFileHashChecker.sln -c Debug
```

```bash
dotnet test HTFileHashChecker.sln -c Debug
```

Outputs: `src/HTFileHashChecker.UI/bin/<Configuration>/net48/` and `.../net461/`. Each contains
`security/advisory-snapshot.json` and `ht-compatibility.json`, generated by the HTREASURE standards targets.

A plain Release build needs the advisory signing key (HTREASURE standards rule):

```bash
dotnet build HTFileHashChecker.sln -c Release -p:HTAdvisorySigningKey=D:\offline\advisory.pem -p:HTAdvisoryKeyId=htreasure-advisory-2026
```

For an internal build only: `-p:HTRequireSignedSnapshot=false`.

## Release packages

```powershell
powershell -NoProfile -File scripts\build-release.ps1 -AdvisorySigningKey D:\offline\advisory.pem
```

Internal test packages: `-InternalAdvisorySnapshot` instead of the key. Other options: `-SkipTests`,
`-SkipCodeSigning`, `-SigningDir`, `-IncludeSubmodulesInSource`.

The script builds, runs all tests, stages both builds, signs this product's executables and DLLs, compiles Setup (which
signs Setup and the uninstaller), builds the portable, source and documentation ZIPs, and writes `SHA256SUMS.txt` last.
Output: `release\v<version>\` (not committed).

The source ZIP contains the committed HEAD of this repository only. The private HTREASURE submodules are left out and
listed by commit in `external/SUBMODULES-NOT-INCLUDED.txt`, because this repository and its releases are public.
`-IncludeSubmodulesInSource` adds them for internal archives; never attach such a package to a public release.

## Prerequisite manifest

`installer/prerequisites.ini` pins the Microsoft .NET Framework installers (URL, size, SHA-256, signer). To refresh it:

```powershell
powershell -NoProfile -File scripts\pin-prerequisites.ps1 -Mode Pin
```

Review the diff before committing. `-Mode Verify` checks the pinned files without changing the manifest.

## Code signing

See [CODE-SIGNING.md](CODE-SIGNING.md). The certificate and its password file live outside the repository
(`C:\HTSoftware\signing` by default).

## Long paths on Windows

The branding kit in `external/HT-Software-Template` contains paths of about 150 characters. Git for Windows refuses
paths longer than 260 characters unless `core.longpaths` is set, so the clone fails in a deeply nested folder
("Filename too long"). Either clone into a short folder such as `C:\Dev`, or use `-c core.longpaths=true` as shown
above (it applies to that clone only; `git config --global core.longpaths true` sets it permanently).
